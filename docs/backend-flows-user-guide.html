1. Executive Overview & Core Concept

1.1 What is WACRM Backend Flows?

WACRM Backend Flows ek high-performance, event-driven server-side orchestration engine hai. Yeh system The Illusion Cafe & Restaurant ke pure operational lifecycle ko automate karta hai:
  • Customer jab WhatsApp par order place karta hai,
  • Kitchen display system (KDS) mein staff accept/reject karta hai,
  • PhonePe UPI payments verify hote hain,
  • Delivery location capture hoti hai aur countdown timers start hote hain.

1.2 Difference: Chatbot Flows vs Backend Flows

FeatureConversational Flows (/flows)Backend Flows (/backend-flows)
Primary ScopeCustomer-facing WhatsApp chat messages, buttons, and AI conversation responses.Server-side business logic, order states, kitchen synchronization, API webhooks, and asynchronous workflows.
Execution ContextNext.js Edge Runtime / Webhook Inbound Pipeline.Asynchronous Node.js Server Runtime with tenant-isolated database state.
Trigger SourceInbound WhatsApp customer text / button clicks.System events (order_event), Webhooks (webhook), Scheduled Cron (schedule), or Manual API dispatch (manual).
Safety GuardrailsInactivity timeout & conversation handoff.SSRF security guards, DAG loop detection, immutable version rollback, and emergency pause circuit breakers.

6. Drag-and-Drop Connections & Logic Branching

6.1 Connecting Nodes

1. Har node ke top par ek Target Port (Blue circle) aur bottom par ek Source Port (Emerald circle) hota hai. 2. Node A ke bottom port se click karke drag karein aur Node B ke top port par drop karein. 3. Edge auto-animate hoti hai to show pipeline direction.

6.2 Condition Node Dual Output Handling

Condition nodes feature two distinct output handles at the bottom:
  • Left Green Handle (true): Is handle se connect kiye gaye nodes tab execute honge jab condition evaluate hokar true nikle.
  • Right Orange Handle (false): Is handle se connect kiye gaye nodes tab execute honge jab condition evaluate hokar false nikle.

` [ 🔀 Check Order Total >= 300 ] / \ (True Path) (False Path) / \ [ Apply ₹0 Delivery ] [ Apply ₹20 Delivery ] `

7. Validation Engine & Pipeline Guardrails

Backend Flows engine visual builder mein real-time graph validation enforce karta hai. Jab tak pipeline valid nahi hoti, workflow publish nahi ho sakta:

1. Cycle Detection (DAG Rule): - System Directed Acyclic Graph (DAG) rules enforce karta hai using depth-first cycle checks. - Agar koi node wapas kisi previous node ko connect karega (infinite loop), validation fail hogi: Pipeline contains a cyclic loop between [node_1] and [node_2]. Loops are not permitted. 2. Single Trigger Constraint: - Har workflow mein exactly ek valid Trigger node hona chahiye. Multiple triggers ya 0 triggers disallowed hain. 3. Orphan Node Warnings: - Agar koi action node canvas par disconnected pada hai, warning show hoti hai taaki unused nodes clean ho sakein. 4. SSRF Security Gate: - Outbound HTTP action nodes loopback (127.0.0.1, localhost), RFC1918 private subnets (10.0.0.0/8, 192.168.0.0/16), aur cloud metadata endpoints (169.254.169.254) ko access nahi kar sakte.

8. Monitoring, Trace Inspector & Intelligent Diagnostics

Execution runs tab (runs) mein past 50 executions ka complete audit trail hota hai.

8.1 Run Record Summary Card

Har run card display karta hai:
  • Status Badge: COMPLETED (Emerald), RUNNING (Sky), ya FAILED (Rose).
  • Release Version: Which snapshot executed (e.g. Run on v2).
  • Trigger Source: How the pipeline fired (via order_event, via manual).
  • Execution Time: Exact duration in milliseconds (42 ms).
  • View Trace: Opens the deep slide-over inspection drawer.

8.2 Execution Trace Drawer (RunTraceDrawer)

Drawer open hone par 3 detailed sections provide karta hai: 1. Step Execution Trace Timeline: - Har individual node ka execution status, start time, completion time, aur millisecond duration. - Expandable I/O inspection: Step ke exact input variables aur returned output data JSON format mein. 2. Trigger Event Payload: - Inbound event ka raw JSON payload (e.g., customer details, ordered items, total amount). 3. Pipeline State & Variables: - Execution ke dauran dynamically create ya modify hue variables.

8.3 Intelligent Failed-Node Diagnostics (diagnostics.ts)

Agar koi node fail ho jaaye, system automatically root-cause diagnosis generate karta hai:

` ┌────────────────────────────────────────────────────────────────────────┐ │ 🚨 Security Guard: SSRF Protection Triggered │ │ Explanation: The outbound request was blocked because the target URL │ │ resolves to a loopback, RFC1918 private network, or cloud metadata IP. │ │ │ │ Actionable Suggestion: Configure a publicly routable HTTPS endpoint │ │ (e.g. your live domain or webhook proxy) instead of 127.0.0.1. │ └────────────────────────────────────────────────────────────────────────┘ `

Diagnostic categories include:

  • ssrf_security_block: Loopback or private IP outbound call blocked.
  • timeout_error: Step exceeded timeout threshold or retry limits.
  • http_status_error: Destination server responded with 4xx or 5xx error.
  • network_error: Connection refused or DNS failure.
  • variable_missing: Node missing mandatory parameter.

10. Version Releases, Rollbacks & Safety Circuit Breakers

10.1 Publishing an Immutable Release

1. Workspace mein apna pipeline structure configure karein. 2. Top-right bar mein Publish Release button par click karein. 3. Modal mein Release Notes / Change Summary likhein (e.g. Added automatic 15-minute kitchen timer webhook). 4. Click Publish Release: Current canvas structure freeze hokar backend_flow_versions mein permanently record ho jaata hai aur workflow status published ho jaata hai.

10.2 One-Click Version Rollback

Agar kisi naye release mein koi regression ya issue observe ho: 1. Version History tab open karein. 2. Har previous release card par Rollback button available hota hai. 3. Rollback par click karne se purana frozen definition draft ke roop mein restore ho jaata hai (audit history delete nahi hoti). 4. Review karke use wapas publish kiya ja sakta hai.

10.3 Emergency Circuit Breaker (Instant Pause)

Agar peak restaurant hours mein kisi workflow ko immediately stop karna ho: 1. Top header bar mein Pause Flow button par click karein. 2. Header par amber PAUSED badge appear ho jaata hai. 3. Is state mein matchesTrigger automatically false return karta hai, jisse koi bhi live restaurant order event workflow execute nahi karega. 4. Click Resume Flow whenever maintenance is complete.
